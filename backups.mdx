EDBB does not provide routine VPS backups. You are responsible for backing up the operating system configuration, application data and anything else needed to recover your service. Keep copies outside the VPS and test them.

<span id="build-a-simple-and-reliable-backup-plan" />

## Choose what to protect

| Data | Backup approach | Recovery check |
| --- | --- | --- |
| Application and website files | Versioned file backups to a separate system | Restore to a temporary directory and compare contents |
| Databases | Database-native dumps or a tested consistent backup method | Import into an isolated database and run application checks |
| Configuration and secrets | Encrypted backups with restricted access | Confirm required keys and configuration can be recovered |
| Entire VPS disk | A separately requested [qcow2 export](/faq/upgrades-downgrades/qcow2-export) | Check image compatibility, capacity and a restore procedure |

<Warning>
  A synchronization job is not automatically a historical backup. Tools such as `rsync --delete` and `rclone sync` can copy accidental deletions to the destination. Use versioned retention and review a dry run before enabling destructive synchronization.
</Warning>

## Establish a backup routine

1. Decide how much recent data you can afford to lose and how quickly you must restore service.
2. Choose a backup schedule and retention period that meet those needs.
3. Store encrypted copies on a separate system. Keep the decryption credentials accessible if the VPS is unavailable.
4. Monitor each job and available backup storage. A scheduled job that failed is not a backup.
5. Restore representative files and databases regularly to an isolated environment.
6. Before an upgrade, reinstall, disk change or cancellation, create a fresh backup and confirm it is usable.

<span id="requesting-a-downloadable-image" />

## Paid disk exports are separate

EDBB offers a manually requested qcow2 disk export for **EUR 25**. A password-protected download link is available for **30 days**. Download and store your own copy within that period. This service is not a recurring backup schedule or an instant snapshot feature.

See [request a qcow2 export](/faq/upgrades-downgrades/qcow2-export). Service [data retention](/faq/billing-lifecycle/data-retention-period) after termination is also separate and must not be used as a backup plan.

Check the IPv6 address, route and DNS separately. Open the [VNC console](/vps-management/enable-vnc-server) before changing network settings.

<span id="inspect-the-guest" />

## 1. Compare the address with the control panel

Open the VPS's **Network** tab. On Linux, run:

```bash
ip -br link
ip -6 addr show
```

The interface should be `UP`. Its global IPv6 address must come from your assigned allocation and use the **/48 interface prefix**. A `fe80::` address alone is only link-local and cannot provide Internet access. An address marked `tentative` is still being checked; `dadfailed` indicates a duplicate-address problem.

<span id="step-2-–-verify-interface-state" />

Use [IPv6 configuration](/vps-management/ipv6-configuration) if the assigned address is missing. Do not choose addresses outside your VPS's allocation.

<span id="step-3-–-test-local-connectivity" />

<span id="test-one-layer-at-a-time" />

## 2. Check the gateway and route

```bash
ip -6 route show
```

Look for a default route through the exact gateway listed in the panel. Replace the example below with that gateway:

```bash
ping -6 -c 4 2001:db8:1234::1
```

If the route is missing or uses the wrong gateway, correct the saved network configuration. A failed ping alone is not conclusive because ICMP can be filtered.

<span id="step-4-–-probe-external-reachability" />

## 3. Test external connectivity and DNS

```bash
ping -6 -c 4 2606:4700:4700::1111
getent ahostsv6 example.com
curl -6 -I --connect-timeout 10 https://example.com
```

| Result | What to check |
| --- | --- |
| Gateway works, external IPv6 does not | Default route, firewall and any current network incident. |
| Numeric IPv6 works, name lookup fails | DNS resolver settings. |
| DNS works, HTTPS fails | The destination, local firewall, application/proxy settings and the route. Test another destination too. |
| Outgoing traffic works, incoming application fails | Application listening address and inbound firewall rules. |

<span id="step-5-–-check-application-bindings" />

## 4. Check the application

```bash
sudo ss -lntup
```

An application listening only on IPv4 will not necessarily accept IPv6. Listening on `::1` allows local access only. Listening on `::` can accept connections on all IPv6 addresses, so check firewall restrictions before changing it. Do not disable the whole firewall to test one port.

<span id="preventive-tips" />

## 5. Check the settings survive a reboot

Once IPv6 works, [save the configuration](/vps-management/ipv6-configuration#keep-the-settings-after-a-reboot) in the network manager used by your OS. Test IPv4 and IPv6 again after a planned restart.

<span id="step-6-–-gather-diagnostics-for-support" />

## Send useful details to support

Email [support@edbb.com](mailto:support@edbb.com) with the VPS IP, time and timezone, failing destination and the address/route results above. Include whether IPv4 still works and whether the problem affects incoming or outgoing connections. Remove passwords and other secrets from logs.

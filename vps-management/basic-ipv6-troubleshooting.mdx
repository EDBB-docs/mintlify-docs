Check IPv6 addressing, routing and DNS separately. Keep the [VNC console](/vps-management/enable-vnc-server) available before changing network settings.

## Inspect the guest

```bash
ip -6 addr show
ip -6 route show
```

Compare the address, **/48 configured prefix** and exact location gateway with the EDBB **Network** tab. Use only your assigned /64-equivalent allocation; the /48 setting does not grant access to the whole location prefix. See [IPv6 configuration](/vps-management/ipv6-configuration).

## Test one layer at a time

1. Check that the intended interface is up and the address is not marked duplicate or tentative.
2. Test the exact gateway from your service record. ICMP filtering can affect replies, so a failed ping alone is not conclusive.
3. Test a known reachable external IPv6 destination by address.
4. Then test name resolution and the actual application protocol.

If numeric destinations work but names do not, inspect the resolver configuration. If the gateway works but external destinations do not, inspect the default route and firewall. Do not disable all firewall rules as a first troubleshooting step.

Binding an application to `::` can expose it on all IPv6 interfaces; restrict access appropriately. Runtime `ip` changes normally do not survive reboot. Make the final correction in your distribution's active network configuration system and verify it after a planned restart.

Send the service IP, timestamps, relevant routes and symptoms to [support@edbb.com](mailto:support@edbb.com), excluding credentials.

The **Settings** tab controls the virtual hardware your operating system sees. Most customers can keep the settings selected by the installer. Change them when an operating system or application needs a particular option.

## Open Settings

Sign in to the [EDBB Control Panel](https://my.edbb.com/clientarea.php), open **Services**, select your VPS, then open **Settings**.

## What the settings do

### Boot & CPU

This first group contains startup timing, firmware, TPM and CPU presentation. **CPU cores vs sockets** changes how the existing vCPUs are presented; it does not add CPU capacity.

### Settings reference

| Setting | How to choose |
| --- | --- |
| **Boot Menu Timeout** | Controls how long the boot menu waits. A longer timeout gives you more time to select recovery media in the console. |
| **CPU cores / sockets** | Controls whether virtual CPUs appear as cores in one socket or as multiple sockets. Match your OS and software's socket limits; this does not change the number of vCPUs in your plan. |
| **CPU Model** | Host CPU Passthrough exposes the host processor's available features. A more generic model may be needed for compatibility. Check application requirements before changing it. |
| **Video Driver** | Select a display adapter supported by your OS. Cirrus is a compatibility option; QXL needs suitable drivers. This controls the virtual display, not RDP access. |
| **Disk Driver** | Virtio is designed for virtual machines and needs OS driver support. Windows or a custom ISO may need Virtio drivers installed before you switch. Legacy IDE is available for systems that require it. |
| **Network Driver** | Virtio is the usual virtual-machine option; E1000 and RTL8139 provide compatibility alternatives. A change may make the OS detect a new adapter, so check its IP configuration afterwards. |
| **VNC Keymap** | Match the console keyboard layout to your keyboard. Check symbols and punctuation before setting passwords in the console. |
| **Description** | A label to help you identify the VPS in your account. It is used as the hostname during a fresh installation; changing it later does not rename an already installed system. |

## Boot mode and TPM

Automated installers choose the boot settings needed by their images. For custom images and ISO installations, **BIOS or UEFI** must match how the system is installed. Changing firmware mode after installation can make an otherwise working disk fail to boot.

A virtual TPM can be required by the OS or used to protect encryption keys. Keep the recovery keys before changing TPM settings. UEFI alone does not mean Secure Boot is enabled. See [boot mode and TPM](/vps-management/efi-vs-bios-and-tpm).

## Apply and check the result

1. Record the current settings, then change only the options you need and click **Apply**.
2. Shut down the operating system cleanly and follow the [full power-cycle procedure](/vps-management/power-cycle-or-reboot-a-vps). A restart inside the OS does not reload all virtual hardware settings.
3. Watch startup in the console. Check disks, network addresses and applications before closing it.
4. If the system no longer starts or connects, restore the previous setting and repeat the power cycle.

If an option is missing or you are unsure which driver an image needs, contact [support@edbb.com](mailto:support@edbb.com) with the VPS IP and operating system.

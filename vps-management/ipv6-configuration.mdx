<span id="ipv6-on-edbb-vps" />

Each VPS receives an IPv6 allocation **equivalent in size to a /64**. It is not routed as a separate /64 subnet. The location uses a shared /48 network, so configure assigned addresses with a **/48 prefix** and the exact location gateway shown for your VPS.

<Warning>
  The /48 interface setting does not allocate the entire /48 to you. Use only your VPS's assigned addresses. The shared policy permits at most **20 stable IPv6 addresses configured simultaneously** and prohibits rotating/random-address IPv6 proxy services.
</Warning>

<span id="step-1-–-grab-the-details-from-the-control-panel" />

## Copy your service values

Open the VPS **Network** tab and record the allocation and gateway. Keep the [VNC console](/vps-management/enable-vnc-server) available before changing networking.

<span id="step-2-–-add-an-ipv6-address-linux-example" />

## Test a Linux configuration

First inspect the existing addresses and routes:

```bash
ip -6 addr show
ip -6 route show
```

The following values are documentation examples, not EDBB assignments. Replace the address, gateway and interface with your verified values. Do not add a second default route if the correct route already exists.

```bash
sudo ip -6 addr add 2001:db8:1234:5678::10/48 dev eth0
sudo ip -6 route add default via 2001:db8:1234::1 dev eth0
```

<span id="step-3-–-test-connectivity" />

Test the actual gateway and a known external IPv6 destination, then name resolution. Inspect firewall rules as well as routes if an application cannot connect.

<span id="best-practices" />

## Make the working settings persistent

Runtime `ip` changes normally disappear after reboot. Use the active distribution configuration system—Netplan, NetworkManager or interfaces files—to persist the verified settings while preserving IPv4 and other addresses. Do not configure the same interface through competing systems.

See [IPv6 troubleshooting](/vps-management/basic-ipv6-troubleshooting) and the [AUP](/acceptable-use-policy).

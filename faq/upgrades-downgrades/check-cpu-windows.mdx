Windows reports the virtual CPU layout presented to the VPS. Use Task Manager or PowerShell to inspect it; the result is not proof of physical host-core exclusivity.

## Task Manager

1. Open **Task Manager** with **Ctrl + Shift + Esc**. If it opens in a compact view, choose **More details**.
2. Select **Performance**, then **CPU**. Expand the navigation menu if you need to see the section names.
3. Read **Virtual processors** below the graph. Other Windows versions may show **Logical processors** and **Cores** instead.

The following example uses Windows Server 2025 on a VPS with **4 virtual processors**. The graphs show a moment in time; utilization changes as applications run.

### Read your CPU allocation

Compare **Virtual processors** (or **Logical processors**) with the vCPU allocation of your VPS. In this example, **Virtual processors: 4** is the relevant count, and **Virtual machine: Yes** confirms Windows is running as a guest.

<Note>
The processor model name contains “64-Core Processor”. That identifies the CPU model exposed to Windows; it does **not** mean this VPS has 64 vCPUs. The socket layout is also virtual and does not establish physical host-core exclusivity.
</Note>

### Show one graph per processor

Right-click inside the CPU graph and choose **Change graph to → Logical processors**. Windows then displays a separate activity graph for each logical processor, as shown in the overview above. To return to a single graph, choose **Overall utilization**.

## PowerShell

```powershell
Get-CimInstance Win32_Processor |
  Select-Object Name, SocketDesignation, NumberOfCores, NumberOfLogicalProcessors
```

For the total logical processor count:

```powershell
(Get-CimInstance Win32_ComputerSystem).NumberOfLogicalProcessors
```

WMIC is deprecated and is not the preferred approach for new instructions. Use the [Microsoft CIM cmdlets](https://learn.microsoft.com/en-us/powershell/module/cimcmdlets/get-ciminstance).

After a resource upgrade, follow its activation instructions and verify the new allocation. See [CPU cores and sockets](/faq/upgrades-downgrades/cpu-cores-and-sockets) and [power cycling](/vps-management/power-cycle-or-reboot-a-vps).
